# Crash hunt (m8/crash-hunt)

A code-level review of the app (App/), BoatCore and BoatAIS, looking for crashes, hangs, leaks, unbounded growth and
isolation holes. It used the 47 rules of the third-party "ios-chaos-monkey" catalogue (data races, memory leaks,
deadlocks, async/await, file I/O, collection mutation, resource exhaustion, Objective-C interop) as a checklist. It
covers concurrency, object lifetimes, resources, isolation and trapping arithmetic. It doesn't fuzz the decoders with
hostile input: a separate chaos suite does that. F2 overlaps with that suite only where a value that decodes fine
later traps in formatting code.

The review changed no app code; every finding that could be shown at package level got a failing test wrapped in
`withKnownIssue`. Branch `m8/crash-fixes` fixed all fifteen (Status column) and removed every wrapper, so the tests in
`Packages/BoatCore/Tests/BoatCoreTests/CrashHuntTests.swift` and `Packages/BoatAIS/Tests/BoatAISTests/CrashHuntTests.swift`
(plus `LivenessTests`, `PublishThrottleTests`, `LatestValueTests`) now guard the fixes. No known issues are left.
Merged with the chaos suite on `m8/beta-fixes` (docs/CHAOS-FINDINGS.md), whose tests that pinned these bugs now assert the
fixes too.

### The F2 sweep

Every `Int(` on a `Double`, `UInt(`, arithmetic index, `!`, `try!`, `as!`, `fatalError` and `precondition` in BoatCore,
BoatAIS and App/ that relay data or sensor values can reach:

| Site | Input | Was | Now |
|---|---|---|---|
| `VesselText.bearing`, `spokenBearing`, `pointIndex` | relay course/heading, compass heading | `Int(degrees.rounded())`, NaN index | normalized first (`normalizedDegrees`), "" when not finite |
| `VesselText.distance`/`spokenDistance` (`roundedFeet`), `spokenSpeed`, `age`, `spokenAge` | distance, speed, report age | `Int(...)` | `Int(saturating:)`; NaN distance reads 0 |
| `CompassStrip.ticks` | compass heading | `Int(floor(...))`, safe only because the heading was finite | empty for a non-finite heading; a finite heading past Int.max (1e300) still trapped, found by the chaos suite (C2) and normalized into [0, 360) first on m8/beta-fixes (871c351) |
| CameraScreen `accuracyPill` | `CLHeading.headingAccuracy` | `Int(...rounded())` | `Int(saturating:)` |
| CameraScreen `maxLanes`/`maxLanesDown` | FOV, view size (F7) | `Int(room / ...)` | `LabelLayout.laneCount` |
| SettingsView `heightFooter` | GPS altitude | `Int(...rounded())` | `Int(saturating:)` |
| `CameraZoom.text` | AVFoundation zoom (F8) | `String(Int(tenths))` | "" when not finite |
| `CameraSession.setZoom` | pinch magnification | division by `displayMultiplier` | ignored when not finite or the multiplier is 0 |

Left as they were, checked safe: `Units` (every value clamped first, NaN to 0), `VesselDetailText.size`/`draught`
(clamped), `SurfaceGrid` (`precondition` reachable only through the memberwise init; `cell()` range-checks before
`Int`), `Browse.bounding` and `MapCardLayout` (`!` behind non-empty guards), `VesselMap.sampleTrain` (constant input),
`TimeZone("UTC")!`, `layer as!` (guaranteed by `layerClass`); `try!` in tests only. No `fatalError` or `UInt(` in app
or package code.

Confidence levels: **proven** (a test shows it), **strong** (clear from reading the code; the trigger is real), and
**speculative** (the mechanism is clear, but whether it happens depends on framework behavior or hardware that can
only be checked on a device).

## Checked and sound

- RelayVesselFeed, closing on stop: `CurrentConnection` plus the `Task.isCancelled` check after `set` close the socket in both orders (the stream ends before or after `connect` returns). Existing test `stoppingTheStreamClosesTheConnection` covers this.
- AsyncStream lifetime: finished exactly once, when the feed task ends. `onTermination` cancels the task and closes the socket. No `CheckedContinuation` exists in the code, so none can be resumed twice or leak.
- The feed loop runs off the main actor (`Task {}` inside a nonisolated method), so decoding is not on the main thread.
- URLSession: the shared session has no delegate (nothing to retain), and every `webSocketTask` is cancelled after `pump` returns.
- Backoff: the exponent is capped at 30, `Duration` is Int128 attoseconds (no overflow), and the delay is capped at 60 s.
- VesselStore `start`/`stop`/`retry`: cancelling the consumer ends `for await` (AsyncStream's `next()` responds to cancellation), which closes the socket. Events buffered in an old stream are dropped by the `isCancelled` check. `trainFlush` is on the main actor and cancelled in `stop`.
- Vanished targets are removed: `remove`, snapshot replacement, and age pruning (600 s for vessels, 60 s for trains). There are no history buffers. The offline freeze is deliberate and bounded.
- AsyncStream uses the default unbounded buffer, but its consumer is the main actor, which only stalls briefly in the foreground. When the app is suspended the socket is suspended too. Acceptable; see F6 for the actual cost.
- Root clocks (CLAUDE.md rule): `NightModeRoot` is a `@State` date moved on by a 60 s `.task`. `SelectionWatcher` uses a 5 s task. `ARLayer` uses a 100 ms task only while something moves (a task, not a nested TimelineView). Settings' `TimelineView(.everyMinute)` is in a sheet attached outside the list's TimelineView. There are no nested TimelineViews. Compass-rate state is read only by `ARLayer`.
- DeviceSensors: `CLLocationManager` is created on the main actor (an `App` `@State`), so its delegate callbacks arrive on main and `MainActor.assumeIsolated` holds. Motion updates go to `.main`. Handlers capture `[weak self]`. CL's delegate is weak. A change of authorization is handled (`location = nil` when denied). If camera permission is revoked, iOS terminates the app.
- Hinge: `UIHingeInteraction` is used only inside `@available(iOS 27.1, *)` / `#available` at its single call site. The handler captures `[weak monitor]`, and `@unknown default` is handled.
- MapViewport debounce: on the main actor, cancels the previous task, `[weak self]`, and checks for an equal region.
- MapKit bridging: `CameraMotion` is a plain unobserved class, so continuous camera changes don't re-render. A zero-size map is guarded (`mapSide >= 1`). `MapRegion.bounding` rejects non-finite input and zero spans.
- AppStorage JSON (`CameraFilter`, `BrowseFilter`): small and sorted. A decode failure gives the default. A separate `Stored` struct avoids `rawValue`/`Codable` recursion.
- The relay address in Settings is a draft committed on submit, so typing doesn't reconnect on each key.
- Force unwraps and casts: `Browse` `min()!`/`max()!` sit behind a `first` guard. `VesselMap.sampleTrain` has a constant, valid input. `TimeZone("UTC")!` is fine. `layer as!` is guaranteed by `layerClass`. `try!` appears in tests only.
- `SurfaceGrid`: the precondition can only fail through the public memberwise init. The bundled grid goes through the failable init, and `.flat` is consistent. `cell()` checks range (NaN fails it) before `Int`.
- Loops: `Sightlines.lineOfSight` (at most 250 steps), `SunPosition.nextTransition` (36 h window plus bisection to 1 s) and `LabelLayout.lanes` are all bounded.
- `CompassStrip.ticks`: `Int(floor(...))` is safe. `half` is guarded to (0, 90), and the heading is finite (`CameraOrientation` rejects NaN through its length guard, and `HeadingFilter` output is finite).
- Units: `clamp` maps NaN to 0. Sizes, draught and speeds are clamped before `Int`. ETA parts are validated.
- `String(format:)`: `%02d` with a Swift `Int` (VesselDetailText.swift:92) works on arm64 because varargs take 8-byte slots and the values are 0-59. `%ld` would be correct. This is cosmetic.
- Camera queue: `startRunning`/`stopRunning` are serialized on one queue and check `isRunning`. Zoom changes go through `lockForConfiguration` on that queue, clamped to the min/max read at configure time.
- Retention: `CameraControlsDelegate` is held strongly by the session object. Block-based KVO observations invalidate on deinit. `PreviewView`'s observer captures `[weak self, weak camera]`.
- Locks: one `Mutex` (`CurrentConnection`). `close()` calls out while holding it, but `URLSessionWebSocketTask.cancel` doesn't re-enter. Sound, though fragile if a future connection's `close()` calls back into `set`.
- `AccessibilityProbe`: DEBUG only, and its recursion stops at depth 80.

## Rules that don't apply here

The catalogue assumes a coordinator-pattern MVVM app (MVVM-C) with SwiftData, Combine and NotificationCenter. This app has none of those:

- **File I/O and persistence** (io-concurrent-file-write, io-filemanager-race, io-plist-concurrent-mutation, io-keychain-thread-safety, io-coredata-cross-thread, io-swiftdata-background, exhaust-file-descriptor-leak): no files, Keychain, Core Data or SwiftData. Persistence is `@AppStorage` on the main actor only.
- **Combine, timers, notifications** (mem-combine-sink-retain, mem-timer-retain-cycle, mem-notification-observer-leak): no Combine, no `Timer`, no NotificationCenter observers.
- **Objective-C interop** (objc-dynamic-dispatch, objc-unrecognized-selector, objc-nsnull-in-json, objc-bridge-type-mismatch, mut-kvo-dealloc-crash): no `@objc` or selectors. JSON goes through `Codable`, where `null` reads as absent. KVO is block-based only (see above).
- **Deadlocks** (dead-semaphore-in-async, dead-recursive-lock, dead-queue-hierarchy, dead-sync-on-main, dead-actor-reentrancy): no semaphores, no `sync` dispatches, one serial queue, no custom actors. `@MainActor` methods don't suspend partway through a state change.
- **Races on shared mutable state** (race-singleton-initialization, race-lazy-initialization, race-array-concurrent-append, race-dictionary-concurrent-write, race-property-access, race-closure-capture-mutation): no singletons beyond `static let` (swift_once), no `lazy var`, no `@unchecked Sendable`, `nonisolated(unsafe)` or `Task.detached`. Mutable state is main-actor isolated or held in a `Mutex`.
- **Task groups and detached tasks** (async-task-group-error, async-detached-task-leak, exhaust-thread-explosion): none in app or package code; no GCD fan-out.
- **mut-enum-future-cases**: `@unknown default` is present where Apple enums are switched over, and the relay's `TargetKind` has `.unknown`.
- **exhaust-memory-warning-ignored**: no caches or images to drop; the largest resident data is the harbor grid (a fixed `static let`).
- **mem-unowned-crash, mem-delegate-strong-reference, mem-closure-retain-cycle**: no `unowned`. Every delegate is weak in the framework or owned on purpose, and every stored closure captures weakly (checked above).

## What this review could not assess without running the app

- F3/F4/F5: how long `configure()` actually blocks, whether two capture sessions fight over the camera during a fold, and the order of `onAppear`/`onDisappear` across the compact/regular branch swap. These need a real iPhone Duo folding while on the Camera tab.
- F6: real AIS message rates in the box, and the main-thread cost per message with side-by-side list and map. Needs a device trace or the opt-in performance tests with a replay feed that sends updates at a realistic rate.
- F1 in the field: how quickly iOS errors a socket after a network change, and how Cloudflare Tunnel behaves when the host stalls.
- F2's MapKit path: whether SwiftUI `Map` throws or clamps on an invalid region center.
- That the device and simulator AVFoundation never report a 0° field of view or a non-finite zoom (F7, F8).
